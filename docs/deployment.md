# Deployment: Vercel (web) + Render (API + Postgres)

```
browser ──https──▶ Vercel: Next.js  ──/api/* rewrite──▶ Render: FastAPI (Docker) ──▶ Render Postgres
```

The browser only ever talks to the Vercel domain. Next rewrites `/api/*` to the API, so the session cookie
stays first-party (ADR-003) and no CORS configuration is needed.

## 1. API + database on Render

1. Render dashboard → **New → Blueprint** → connect GitHub → pick `wcmalfeld/HVAC-Studio`.
2. Render reads [`render.yaml`](../render.yaml) and proposes `hvac-studio-api` (Docker web service) and
   `hvac-studio-db` (Postgres 16). Click **Apply**.
3. Wait for the first deploy. The container runs `alembic upgrade head` before starting, so the schema is
   created automatically. `SECRET_KEY` is generated by Render; `DATABASE_URL` is wired from the database.
4. Check `https://hvac-studio-api.onrender.com/api/v1/health` (your URL is on the service page) returns
   `{"status":"ok","database":"ok",…}`.

## 2. Web on Vercel

1. Vercel dashboard → **Add New → Project** → import `wcmalfeld/HVAC-Studio`.
2. **Root Directory:** `apps/web` (Vercel detects Next.js and the pnpm workspace; leave the build and install
   commands at their defaults).
3. **Environment variables** (Production and Preview):
   - `API_ORIGIN` = your Render API URL, e.g. `https://hvac-studio-api.onrender.com` (no trailing slash).
     It is read at **build** time (rewrites are compiled in), so redeploy after changing it.
   - `ENABLE_EXPERIMENTAL_COREPACK` = `1` (use the pnpm version pinned in `package.json`).
4. Deploy, open the `*.vercel.app` URL, register an account.

## Updating
Pushes to `main` redeploy both. Vercel also builds a preview for every branch/PR (previews talk to the same
production API unless you give them a different `API_ORIGIN`).

## Free-tier limits (as configured)
| | Free | Upgrade |
|---|---|---|
| API | sleeps after ~15 min idle; first request can take ~1 min | `plan: starter` |
| Uploaded drawings | stored on the container disk → **lost on every redeploy/restart** | `starter` + the `disk:` block in `render.yaml` |
| Database | **expires 30 days after creation** | `plan: basic-256mb` |

Upgrade before anyone relies on the data. Moving uploads to object storage (an `S3Storage` behind
`app/services/storage.py`) removes the need for a disk.

## Known follow-ups
- **Rate limiting by IP:** login rate limits key on IP + email. Behind Vercel → Render the API sees the
  proxy's address, not the visitor's, so limits are effectively per email. Add the proxies to
  `TRUSTED_PROXIES` once their egress ranges are pinned down.
- **Demo data:** `scripts/seed_demo.py` is not run in production. Run it from the Render shell (paid plans)
  if you want the demo account there.
